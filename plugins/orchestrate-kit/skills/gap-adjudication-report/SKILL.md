# 缺口盤點／裁決報告產出規範

產出「略過未處理項目」「待裁決事項」「遷移缺口」這類決策支援文件（通常是 HTML）時，依本規範執行。目標：裁決人看完報告就能下決定，不必自行查證或在長文件裡找位置。

來源：這份規範來自一次裁決盤點的兩輪修正——第一版只有文字、缺視覺化，補上 UI 定位、證據分級與索引後，裁決人才看得完就能下決定。

## 報告結構（由上而下）

1. **結論先行**：第一屏直接回答關鍵問題（例：「目前還不能改 Verified」），附編號的建議裁決順序清單。
2. **一頁裁決索引表**：欄位＝ID、一句話事實、收尾關係（阻擋／範圍須明文／可另案）、建議下一步；每列連結可直接跳到該項的證據區塊、截圖或網址，不要求讀者自行在長文件裡尋找。
3. **證據基準說明**：查證日期、程式基準（branch＋commit）、資料庫基準，與證據來源分類圖例。
4. 各項目詳述卡片 → 分類彙總（需業務確認／UIUX 佇列／純工程收尾／已有歸屬附註）。

## 每個項目的硬性要求

### 先判斷有無 UI 版位

- **有 UI 版位**：必附四件——操作路徑（頁面 → 分頁 → 區塊）、UI 參考頁網址、目前系統網址、框選截圖。只文字描述問題不合格。
- **截圖框選完整影響範圍**，不是只框最顯眼的入口。入口與範圍分色標注並各自加說明標籤（例：A1 入口是「依模組」按鈕，真正範圍是下方整個彙整區——紅框標入口、橘框標全範圍）。
- **無 UI 版位**：改附可執行的驗證方法——帳號情境、路由、Controller、Repository、資料表與觸發鏈（缺陷位置＋呼叫入口＋觸發流程逐步）。

### 證據來源分類（不可混淆）

圖像證據分三種，每張圖說都標明來源，不得讓讀者誤認：

| 種類 | 定義 | 標注要求 |
|---|---|---|
| UI 參考頁截圖 | 專案的 UI 參考頁或原型頁畫面 | 標「UI 參考頁」＋網址 |
| 目前系統截圖 | 登入實際環境的畫面 | 標「目前系統」＋網址 |
| 依程式重建的版位示意 | UI 參考頁與系統都沒有此畫面時，依樣板或程式原樣文字重建 | 明寫「不是系統截圖」＋來源檔案與行號 |

寫「哪個身分在哪個畫面會遇到什麼」前，先列畫面入口條件（按鈕／選單的顯示與可用條件、整頁唯讀條件）與出處，並盡量以瀏覽器重現；後端放行不等於畫面上做得到。未重現的標「依程式推得、未在畫面查證」。

### 交叉查證

- 每項結論至少交叉比對 UI、程式、API、資料庫中**適用**的來源；單一來源不足以下結論。
- 必附：檔案路徑＋行號、資料筆數、查證日期。數字當日親自查證，不轉抄舊文件或 SPEC 既載值。
- 對照表格式：畫面現值 vs 資料庫實證 vs 缺少的定義（口徑歧義逐項點名）。

## 掃描範圍（防漏項）

不只盤點 SPEC 已列缺口，另外全掃：

- 列表頁——含頁首摘要區、KPI 統計卡
- 詳情頁每一個頁籤
- 所有 Modal
- 樣板內固定值（grep 寫死的數字與文字）

理由：只查規格已登記的缺口時，容易漏掉列表頁摘要區整組寫死的假資料。

## 呈現

- 視覺化必備：阻塞關係圖、進度圖、選項對照長條圖、分工泳道等 inline SVG；有安裝圖表類的 skill 或 plugin 時依它（例：統計圖用 dataviz、關係與流程圖用 diagram-design），沒有時直接寫 inline SVG。
- 截圖放報告同名 `.assets/` 資料夾，HTML 以相對路徑引用；其餘 CSS／SVG 一律內嵌，不引外部資源。
- 語言與用語依專案規範。
- 「工程視角建議」只標在工程可判斷的項目；產品行為選擇列選項與資料事實，不代裁。
- 只呈現最新狀態：已修復／已處理的項目直接從圖、卡片、表格拿掉，剩餘項目重新編號；不加「已修復」標記，也不在副標或頁尾寫剩餘計數。

## 專案對照

- UI 參考頁網址、目前系統網址、驗收帳號與舊系統查證基準，以各專案的 CLAUDE.md／CLAUDE.local.md 為準；本 skill 不記單一專案的網址與帳號。

## 交付前驗收

- 用瀏覽器實際渲染整份報告（Playwright 截圖逐圖檢視），console 無 JavaScript 錯誤。Playwright MCP 擋 `file:` 協定：改以本機 HTTP 伺服器只提供報告 HTML 與其素材的暫存複本來渲染，驗完刪除複本；Playwright 產物放在 Playwright MCP 的輸出目錄，不進 repo。頁面有 `scroll-behavior:smooth` 時，`scrollIntoView()` 後同一次 evaluate 量到的是捲動前座標：先插入 `*{scroll-behavior:auto !important}`、以 `behavior:'instant'` 捲動並等 500ms 以上，再用另一次 evaluate 量框選座標。圖片為 `loading="lazy"` 時，`complete`／`naturalWidth` 會把還沒捲到的圖誤判為破圖，改逐張 `fetch(HEAD)` 看狀態碼。
- 索引表每個連結實際點得到目標。
- 對照「掃描範圍」清單逐項確認都掃過，不足處在報告內明寫未掃原因。
