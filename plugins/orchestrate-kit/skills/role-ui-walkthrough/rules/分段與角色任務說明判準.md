# Rule 1 - 任務說明寫角色知道的事，不寫畫面

- Level: `MUST`
- 任務說明只包含：角色是誰、手上有的資料與檔案、測試者本來就知道的流程知識、要完成的事、工具與限制、每一步的紀錄方式、停下回報的條件、回報格式。
- 不寫任何畫面上的東西：按鈕或選單的名稱與位置、頁面網址的路徑、欄位順序、要點幾下。入口只給網站首頁；角色從已登入的狀態開始時，只說「已登入，停在後台的某一頁」。
- 要完成的事用角色的目的陳述，不用操作陳述。

## Good Example

```md
第一輪：會員林書豪傳訊息說他註冊好了。請找到他的申請並核准。然後停下回報。
```

## Bad Example

- 入口、選單名稱與按鈕名稱都寫出來，agent 照著點就做完，量不到「找不找得到入口」。

```md
第一輪：到左側選單的「會員總覽」，在「待審核會員」區塊按林書豪那一列的「核准」。
```

# Rule 2 - 給測試者本來就知道的流程知識

- Level: `MUST`
- 流程層級的事要寫進任務說明：誰審核、審核前後能做什麼、測試期間哪些步驟會自動成功（例：付款）、哪一個角色要先做哪件事另一個角色才能繼續。
- 判斷方式：一位拿到測試說明的人類測試者會不會被告知這件事。會，就寫；只有看過畫面或程式才知道的，不寫。
- 不為了觀察 agent 猜不猜得到而隱瞞流程知識：隱瞞後卡住的位置反映的是缺少說明，不是畫面的問題。
- 以「你事先知道的流程（測試人員都知道）」為段落標題逐條編號，段落最後寫「除了以上，你不知道任何畫面長什麼樣、按鈕在哪裡」。

## Good Example

```md
## 你事先知道的流程（測試人員都知道）
1. 會員用邀請連結註冊後，帳號要審核，邀請的帶領人或管理者都可以審核。
2. 審核通過後，會員登入、報名讀書會並付款（測試期間付款自動成功）。
3. 會員付款後，帶領人要按「開始」，這一期才正式開始。

會員那一側由別人操作。除了以上，你不知道任何畫面長什麼樣、按鈕在哪裡。
```

## Bad Example

- 第 3 條把入口位置寫了出來，屬於畫面知識；第 1、2 條被省略，agent 在等待審核時無從判斷是畫面沒說還是流程本來如此。

```md
## 你事先知道的流程
1. 「開始」按鈕在儀表板的「待帶領人開始」區塊。
```

# Rule 3 - 每一輪要有「畫面有沒有回答」的問題

- Level: `MUST`
- 每一輪任務做完後，要求 agent 回答幾個只能從畫面得知的問題，並寫出依據是畫面上的哪段文字。問題取自這個角色此刻合理會想知道的事：
  - 動作有沒有成功：「你怎麼從畫面知道已經通過了？」
  - 自己的待辦：「現在有幾件事在等你處理？你從畫面哪裡看出來？」
  - 對方看得到什麼：「對方會在哪裡看到你剛做的事？你從畫面上知道嗎？」
  - 目前的狀態：「這個讀書會現在會員報得了名嗎？依據是畫面上的什麼？」
  - 等待中：「回報畫面上告訴你要等待的文字（沒有就寫沒有）。」
  - 審核類畫面：「在回報裡列出審核畫面上看得到哪些資料。」
- 「看得到結果但資訊不足」「動作後沒有回饋」這類發現主要來自這些回答；只要求做完的任務說明量不到。

## Good Example

```md
第三輪：找到他這週交的心得並回覆。然後回答：
- 現在有幾位會員的心得在等你回覆？你從畫面哪裡看出來？
- 會員會在哪裡看到你的回覆？你從畫面上知道嗎？
- 你剛設定的每週進度，會員看得到了嗎？依據是畫面上的什麼？
```

## Bad Example

```md
第三輪：找到他這週交的心得並回覆，做完回報「完成」。
```

# Rule 4 - 依賴順序分段，一個 agent 不超過約 60 步

- Level: `MUST`
- 把旅程排成段落表：段落、角色、前置條件（哪個角色先做了什麼）、交接方式（另一個角色 agent，或主控代做）。前置條件由其他角色完成的地方，就是 agent 的停下點。
- 一個 agent 的步數上限：桌機寬度（1280×720）約 60 步，手機寬度（390×844）約 100 步。實測參考值：手機 48 步用約 15 萬 tokens、104 次工具呼叫、約 13 分鐘；桌機 57 步到約 22 萬 tokens。任務說明把步數上限列為停下條件。
- 一個角色的工作超過上限時拆成多個 agent（例：「註冊到上線」與「日常操作」）。後一個 agent 從主控準備好的登入狀態開始，任務說明用一段「你上週已經……」交代前情，不讓它重做。
- 同一個 agent 的工作可以分成多輪：每輪做完停下回報、等訊息再做下一輪，輪與輪之間瀏覽器狀態保留。
- 主控代做的範圍：不是這次觀察對象的步驟、替 agent 準備前置狀態的步驟。主控代做的步驟不產生發現，截圖存到 `_setup/`，可當手冊素材。

## Good Example

```md
| 段落 | 角色 agent | 前置條件 | 交接 |
| --- | --- | --- | --- |
| 1 註冊、開讀書會送審、取得邀請連結 | 帶領人甲（3 輪） | 無 | 帳號審核、讀書會審核由管理者 agent 做 |
| 2 審核帶領人、審核讀書會 | 管理者（2 輪） | 段落 1 送出 | 主控通知帶領人甲繼續 |
| 3 會員註冊、報名付款、交一篇心得 | 會員 | 邀請連結（主控讀回） | 核准與開始由主控代做 |
| 4 核准、開始、設定進度、回覆心得 | 帶領人乙（3 輪） | 段落 3 各階段 | 會員側由主控代做 |
```

## Bad Example

- 一個 agent 做完一個角色的所有事，桌機寬度下超過 100 步，context 在後半段不足。

```md
| 段落 | 角色 agent |
| --- | --- |
| 帶領人的所有操作（註冊到回覆心得） | 帶領人 |
```

# Rule 5 - 停下條件與卡住的定義寫進任務說明

- Level: `MUST`
- 任務說明列出停下回報的條件，至少包含：這一輪的事做完；等待其他角色；卡住；需要系統以外的東西（簡訊驗證碼等）；累計超過步數上限。
- 卡住的定義固定為：同一件事連續 3 次結果與預期不符，或畫面上找不到任何看起來相關的入口。同一段寫明「像一般使用者那樣操作，不逐一嘗試每個按鈕」。
- 回報格式只收事實：完成或未完成、依據（畫面上的文字）、最後一張截圖檔名、累計步數、遇到的不順（每項附截圖檔名與一句描述）。寫明「只寫遇到什麼，不寫改善建議」。
- 畫面不會自己更新別人剛做的事時，要 agent 像一般使用者那樣處理（切換頁面或重新整理），並記下「需要重新整理才看得到」。

# Rule 6 - 安全限制逐條寫明

- Level: `MUST`
- 剪貼簿：禁止 Control+V、Control+C、Control+X 與畫面上的「複製」按鈕或圖示。瀏覽器與執行的電腦共用剪貼簿，agent 為了確認複製有沒有成功而貼上時，會把電腦剪貼簿裡與測試無關的內容貼進頁面並截進圖。（實例：第一次執行時有兩張截圖因此被隔離。）
- 帳密：管理者等高權限帳號的帳密不寫進任務說明，agent 從主控準備好的登入狀態開始，並寫明「不要登出」。一次性的測試帳號可以把帳密寫進任務說明。
- 動作範圍：環境裡有其他資料時，寫明除了被交辦的對象，不得對其他帳號或資料按下會改變資料的按鈕（通過、退件、停權、刪除、儲存、退款等）；不確定某個按鈕會不會改變資料時不按，寫進紀錄。
- 個人資料：角色不想提供的欄位（例：身分證字號）寫明「畫面要求必填就停下回報」。
- 導航：禁止自己輸入網址、開新分頁、切換分頁、改視窗大小。

# Rule 7 - 角色資料要足夠填完表單

- Level: `SHOULD`
- 角色設定寫出姓名、職業背景、不是工程師、用手機或電腦。
- 手上的資料逐項列出：帳號、手機、密碼、要上傳的檔案路徑、表單會問到的專業資料（證照字號、活動名稱與價格等）。
- 沒列到的欄位，寫明「照這個角色合理回答，並在紀錄註明『自行設定』」。
- 帳號照專案測試資料的命名規則產生，讓專案既有的清除指令清得掉。

# Rule 8 - 要求 agent 標出事先知識

- Level: `MUST`
- subagent 會自動載入專案的規則檔、記憶索引與最近的提交訊息，工具限制管不到這一項。任務說明要求兩件事：
  - 每一步用到「任務說明以外、事先就知道的系統知識」時，標註「用到事先知識：〈是什麼〉」。
  - 全部做完時，逐條列出開始操作前已經知道哪些關於這個系統的事（任務說明寫的不用重複），沒有就寫沒有。
- 這兩份自述寫進主控筆記的判讀限制；受影響的段落在現況表註明。

# Rule 9 - 專案第一次執行先試跑一段

- Level: `SHOULD`
- 選一段前置條件最少、其餘交接主控能代做的段落當試跑，只派一個 agent。
- 試跑要確認三件事：這個專案上只靠截圖操作得了；攔截有效；步數與 token 用量在預期內。同時記下專案特有的限制。結果向使用者回報後再擴大。
- 專案記憶已有上次的準備事實、且瀏覽器工具與網站都沒有大改時，可以不試跑。

# Rule 10 - 只問專案規則沒有答案的事

- Level: `MUST`
- 要問使用者的只有下列三項之中專案規則沒寫明的，一次問完並附推薦：
  - 付費的外部呼叫：推薦探索回合攔截成固定回應，要用真實呼叫重拍手冊時先報次數與費用。
  - 產出位置：進不進版控。
  - 手冊的第一位讀者。
- 視窗大小、截圖間隔、步數上限、run 目錄命名照本檔與瀏覽器準備的規則決定，不問。
