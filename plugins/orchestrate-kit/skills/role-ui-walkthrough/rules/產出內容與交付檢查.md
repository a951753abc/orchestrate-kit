# Rule 1 - 產出只以主控筆記為來源

- Level: `MUST`
- 現況表、操作手冊、裁決報告的事實、狀態、收尾關係、修改類別、要裁定的事，一律照主控筆記寫。產出文件的 agent 不增減項目、不改判定、不新增產品選項。
- 工單的共同必讀：主控筆記、各角色 agent 的回報全文、各 run 的逐步紀錄。素材沒有的畫面或步驟不補寫。
- 產出文件的 agent 開圖後發現截圖與筆記的事實不符時，在該項照實寫「截圖上看不到：〈哪一句〉」並在回報列出；主控依回報更正後，以卡片為準並在筆記或報告的證據基準註明差異。
- 使用者只要其中幾份產出時，只做那幾份；主控筆記仍然要寫。

# Rule 2 - 現況表的內容

- Level: `MUST`
- 第一屏：一段話說明這份文件是什麼（哪一天、用 agent 只看畫面操作哪個環境的結果）、三個數字（旅程步驟數、卡住次數、用到提示次數）、到操作手冊與裁決報告的連結。
- 旅程圖：畫成 inline SVG（有安裝 `diagram-design` plugin 時依它，沒有時直接畫），每個步驟一個節點，依角色分列，節點以顏色加文字標示狀態，節點連到手冊的對應步驟。步驟多時分成兩張，兩張用同一個縮放比例。
- 現況表：一列一個旅程步驟，欄位＝編號、旅程步驟、角色、狀態、一句話依據、到手冊的連結。狀態用文字加顏色標籤，顏色之外一定有文字。
- 這次沒有操作的範圍：逐項列出。
- 判讀限制：3～5 個條列。
- 頁尾：證據基準（日期、程式的 branch 與 commit、網址、視窗大小）。

# Rule 3 - 操作手冊的內容

- Level: `MUST`
- 每個角色一個區塊，頁首有角色切換的錨點連結；每個旅程步驟一個小節，id 為 `step-<編號>`，編號與現況表一致。
- 每個小節：標題與一句話目的；「開始之前」（這一步需要先有什麼）；操作步驟；「目前要留意的地方」。
- 操作步驟照 agent 實際走通的路徑寫，一步一張截圖加一句說明（按哪裡、填什麼、畫面出現什麼）。走錯與回頭的步驟不收；同一畫面連續填欄位可以合成一步。
- agent 卡住過的步驟，手冊直接寫正確的入口，並在留意事項寫明哪個畫面沒有這個入口。
- 「目前要留意的地方」只列素材裡真的遇到的現況，一句話，連到裁決報告的對應項目；不寫改善建議或評價。
- 每個角色區塊開頭列出這次示範用的資料（帳號顯示名稱、測試用 Email、活動名稱）。不寫密碼與其他個人資料。
- 主控代做、沒有 agent 截圖的步驟，寫明由主控預先完成，可用 `_setup/` 的截圖。
- 受事先知識影響的步驟在該小節註明。

# Rule 4 - 截圖的取用

- Level: `MUST`
- 用到的截圖複製到文件同名的 `.assets/` 資料夾，檔名 `<run>-<步驟>.png`（主控的截圖用 `setup-<原檔名>`）；HTML 以相對路徑引用。素材目錄只讀，不搬移、不改名、不修改原檔。
- 引用一張截圖之前用 Read 開圖確認內容。
- 圖說固定格式：`目前系統｜<網址或路由>｜<角色與帳號>｜<日期>｜<run> 步驟 <NNN>`。網址取自逐步紀錄；紀錄沒有的寫路由樣式並註明「網址依畫面推定」。
- `<img>` 寫 `width`、`height`（等於截圖的視窗大小）、`alt`、`loading="lazy"`。
- 隔離清單上的截圖不得開啟、複製或引用；那幾步不寫進手冊。工單的禁止事項要逐一列出檔名。
- 不引用外部資源：CSS、SVG 全部內嵌，不放 `<script src>`、`<link rel=stylesheet>`、`@import`、外部圖片。

# Rule 5 - 裁決報告照 orchestrate-kit:gap-adjudication-report，加上這幾項

- Level: `MUST`
- 報告結構、框選截圖、證據來源分類、交叉查證與一頁索引照 `orchestrate-kit:gap-adjudication-report`。
- 這類報告的截圖全部是「目前系統」的截圖；專案沒有 UI 參考頁時在證據基準寫明。
- 證據基準另外寫：判讀限制、攔截的固定回應、哪些截圖主控親自看過、程式引用抽查的處數。
- 第一屏的建議裁決順序照主控筆記：先阻擋，再診斷後修，再範圍須明文，最後可另案依群組分批。
- 「掃描範圍」寫明這次只涵蓋旅程經過的畫面，沒有逐頁全掃，並列出沒操作的功能。

# Rule 6 - 交付前的檢查

- Level: `MUST`
- 靜態檢查：每份 HTML 都以檢查腳本驗證圖片與連結目標存在、頁內與跨檔的錨點對得上、沒有外部資源、圖片屬性齊全、沒有引用隔離清單上的截圖。必要的 id（現況表的區塊、手冊的每個 `step-<編號>`、報告的每張卡片）用 `--ids` 列出；現況表到手冊、手冊到報告的連結用 `--require-hrefs` 列出；隔離清單用 `--forbid` 列出。
- 瀏覽器渲染：依 `orchestrate-kit:gap-adjudication-report` 的交付前驗收，以只綁 loopback 的本機 HTTP 伺服器提供暫存複本。桌機寬度（1280）與手機寬度（390）各看一次：
  - 圖片全部回 200（lazy 圖片以 `fetch` 判定）。
  - 框選都在圖片範圍內。
  - 頁內連結都有目標；從索引點一個項目、從旅程圖點一個節點，確認到得了。
  - 沒有水平捲動（`scrollWidth` 等於 `clientWidth`）；有的話找出超出的元素修正後重驗。
  - console 沒有 JavaScript 錯誤。
- 驗完關閉瀏覽器、停掉暫存的 HTTP 伺服器、刪除暫存複本，並確認沒有殘留行程。Windows 上以命令列比對找伺服器的 PID（`Get-CimInstance Win32_Process`）；`Get-NetTCPConnection` 的 OwningProcess 可能回 0。
- 產出不進版控時，以 `git status --porcelain` 輸出為空確認 repo 沒有被動到。
- 文字層：內部用詞（檔名代稱、工單編號、「notes」這類工作檔的名字）不出現在給讀者的文件裡；要提到主控筆記時用「主控筆記」並在證據基準說明它是什麼。

# Rule 7 - 回報要補的內容

- Level: `MUST`
- 結論一句話：這一趟走不走得完、能不能交給真實使用者、各狀態的步驟數。
- 文件位置與建議先看哪一份。
- 待使用者裁定的事：隔離的截圖（刪除或保留）、裁決項目與建議順序。
- 已知限制：手冊的截圖來自探索回合（測試帳號、攔截的固定回應）；掃描範圍；留在資料庫的測試資料與清除方式。
- 未執行項目：產品修正（等裁定）；以真實呼叫重拍手冊（先報次數與費用）。
- 產出含系統截圖。要發布到本機以外的地方（網頁、雲端文件）之前先問使用者。
