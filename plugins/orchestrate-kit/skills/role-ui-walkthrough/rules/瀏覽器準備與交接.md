# Rule 1 - run 目錄放在 Playwright MCP 的輸出目錄底下

- Level: `MUST`
- Playwright MCP 只准把檔案寫進它的輸出目錄與 session 工作目錄，其他路徑回 `File access denied`。截圖路徑一律用輸出目錄底下的絕對路徑。
- 一個角色 agent 一個 run 目錄，命名 `<角色>-<序號>`（例：`host-01`、`member-01`）。固定結構：

```text
<Playwright MCP 輸出目錄>/<測試名稱>/
  <run>/shots/    角色 agent 的截圖（NNN.png、NNNa.png，三位數步驟編號）
  <run>/log/      角色 agent 的逐步紀錄（steps-001-010.md、steps-011-020.md…）
  <run>/album/    這個角色要上傳的檔案（照片、證照圖檔）
  _setup/         主控準備與代做時的截圖、storage state
  _tooltest/      派出前確認工具可行的截圖
```

- 要上傳的檔案由主控準備，不放含真實個人資料的圖片。

# Rule 2 - 每個角色 agent 一個隔離的 context

- Level: `MUST`
- 用 `browser_tabs` 的 `action: "new"` 帶 `isolatedContext: "<名稱>"` 開分頁，各角色的登入狀態互不影響。預設 context 可能留有先前的登入狀態，不給 agent 用。
- 視窗大小在該分頁以 `page.setViewportSize` 設定：手機角色 390×844，桌機角色 1280×720。任務說明寫同一組數字；截圖不用 `fullPage`，圖上的座標就是點擊座標。
- 以 `context.addInitScript` 隱藏會擋住畫面的開發工具浮動元件；手機寬度另外隱藏捲軸。專案的 e2e 設定已列出要隱藏的元件時，沿用同一份清單。
- 設在 context 上的 `route` 與 `addInitScript`，在 subagent 接手操作後仍然有效。

## Good Example

```js
// browser_tabs: { "action": "new", "isolatedContext": "wt-member", "url": "about:blank" }
// 接著在該分頁執行（引號原樣保留）：
async (page) => {
  const ctx = page.context();
  await page.setViewportSize({ width: 390, height: 844 });
  await ctx.addInitScript(() => {
    const add = () => document.documentElement.appendChild(Object.assign(
      document.createElement('style'),
      { textContent: '#dev-widget{display:none!important;pointer-events:none!important} ::-webkit-scrollbar{display:none!important} html{scrollbar-width:none!important}' }
    ));
    if (document.documentElement) add();
    document.addEventListener('DOMContentLoaded', add);
  });
  return { url: page.url(), vp: page.viewportSize() };
}
```

## Bad Example

- 直接用預設 context 的分頁：先前 e2e 留下的登入狀態還在，agent 第一步看到的是別人的後台。

```js
// browser_navigate: { "url": "http://bookclub.test/" }  ← 預設 context
```

# Rule 3 - 付費或會對外發送的呼叫，在 context 上攔截

- Level: `MUST`
- 先從專案規則與專案記憶找出所有付費或對外的 endpoint（影像辨識、估算、簡訊、金流、寄信）。找不到清單時，派唯讀 agent 從程式列出後再攔截，不憑猜測。
- 用 `context.route` 攔截；只處理會觸發計費的 method（通常是 POST），其餘 `route.fallback()`。回應用固定內容，欄位照 API 的真實回應格式。要讓 agent 看到等待中的畫面時，回應前加 1～3 秒延遲。
- 專案已有 mock 設定（例：簡訊 mock）時，先確認它是開啟的，只讀那一個設定鍵。
- 固定回應的內容寫進主控筆記的證據基準；手冊用到這些畫面時註明是攔截的固定結果。
- 要改用真實呼叫時，先向使用者報次數與費用並等同意。

## Good Example

```js
async (page) => {
  const ctx = page.context();
  await ctx.route('**/api/summarize-note', async route => {
    if (route.request().method() !== 'POST') return route.fallback();
    await new Promise(r => setTimeout(r, 2500));
    await route.fulfill({
      status: 200,
      contentType: 'application/json',
      body: JSON.stringify({ summary: '（測試用固定摘要）第三章談習慣的形成。', tokens: 0 })
    });
  });
  return 'routes ready';
}
```

## Bad Example

- 只攔了畫面上看得到的那一個 endpoint；同一個流程稍後還會呼叫另一個付費的估算 endpoint，探索回合就真的送出了請求。

```js
await ctx.route('**/api/summarize-note', route => route.fulfill({ status: 200, body: '{}' }));
// 沒有查專案規則列的第二個付費 endpoint
```

# Rule 4 - 帳密不進 agent 的 context，登入狀態由主控載入

- Level: `MUST`
- 高權限帳號（管理者等）：用一支本機腳本以環境變數的帳密登入，只把 storage state 存成檔案放在 `_setup/`。帳密不輸出、不寫進腳本檔、不寫進任務說明。`browser_run_code_unsafe` 的工具輸出會印出程式全文，所以帳密也不能出現在 run_code 的程式裡。
- `browser_run_code_unsafe` 的執行環境沒有 `process`、`require`、dynamic import，讀不到本機檔案。載入 storage state 的做法：先開到目標網站同一個 origin 的任一頁，在頁面加一個 file input，用 `page.setInputFiles` 放入 storage state 檔，在頁內讀出內容，再以 `context.addCookies` 與逐筆寫入 localStorage 套用，最後前往登入後的頁面並截圖確認。
- 角色 agent 從已登入的頁面開始；任務說明的第一步要它檢查網址前綴，是登入頁就停下回報。
- storage state 檔不進版控，測試結束後隨 run 目錄一起清掉。

## Good Example

```js
// 分頁已在 http://bookclub.test/admin/login（同一個 origin）
async (page) => {
  await page.evaluate(() => {
    const i = document.createElement('input');
    i.type = 'file'; i.id = '__ss';
    document.body.appendChild(i);
  });
  await page.setInputFiles('#__ss', '<輸出目錄>/<測試名稱>/_setup/admin-state.json');
  const s = await page.evaluate(async () => JSON.parse(await document.querySelector('#__ss').files[0].text()));
  await page.context().clearCookies();
  await page.context().addCookies(s.cookies);
  const ls = (s.origins[0] && s.origins[0].localStorage) || [];
  await page.evaluate(items => items.forEach(i => localStorage.setItem(i.name, i.value)), ls);
  await page.goto('http://bookclub.test/admin');
  await page.waitForTimeout(2500);
  await page.screenshot({ path: '<輸出目錄>/<測試名稱>/_setup/admin-01-home.png' });
  return { url: page.url(), cookieNames: s.cookies.map(c => c.name) };
}
```

## Bad Example

- run_code 的環境沒有 `import`，這段會直接失敗；把帳密寫進程式則會被工具輸出印出來。

```js
async (page) => {
  const fs = await import('node:fs/promises');
  const s = JSON.parse(await fs.readFile('admin-state.json', 'utf8'));
}
```

# Rule 5 - 派出前確認只靠截圖操作得了

- Level: `MUST`
- 在隔離 context 做一次「`page.mouse.click(x, y)` → `page.screenshot({ path })` → 用 Read 看圖」，確認三件事：
  - 截圖尺寸等於設定的視窗大小。
  - 點擊座標與截圖座標一致（點到了預期的元素）。
  - 工具回傳不含頁面結構，也不回傳影像。頁面快照另存成 .yml 檔，任務說明禁止 agent 讀取；agent 要自己 Read PNG。
- 角色要上傳檔案時另外確認檔案選擇：座標點擊會開檔案選擇視窗的元素後，工具回傳只有 Modal state，接著用 `browser_file_upload` 交出檔案路徑。不在 run_code 內自己等 `filechooser` 事件，那樣會留下未處理的 Modal state。
- 確認用的截圖存 `_tooltest/`。

# Rule 6 - 每一步存兩張截圖

- Level: `MUST`
- 每一步的 run_code 做「動作 → 0.3 秒後截 `NNNa.png` → 再過 1.7 秒截 `NNN.png`」。只截一張會漏掉短暫的畫面與一閃而過的提示訊息。（實例：付款完成畫面只顯示 2 秒，agent 2.5 秒後才截圖，回報成「沒有結果畫面」。）
- agent 平常只 Read `NNN.png`，懷疑中間閃過訊息時才 Read `NNNa.png`。主控查證「沒有回饋」類的發現時兩張都看。

# Rule 7 - 同一時間只有一個 agent 操作瀏覽器，通知前切回它的分頁

- Level: `MUST`
- Playwright MCP 的操作對象是目前分頁。一個角色 agent 操作時，主控與其他 agent 都不使用瀏覽器。只讀文件與程式的查證 agent 可以並行，它的任務說明要寫明不得使用任何瀏覽器工具。
- agent 停下等待時：主控（或另一個角色 agent）完成那一步之後，先用 `browser_tabs` 的 `select` 切回等待中 agent 的分頁，再以 SendMessage 通知。
- 通知只陳述這個角色會被告知的事實與下一輪的任務，不寫畫面位置。
- 主控代做其他角色的步驟時用 locator 操作，每步截圖存 `_setup/`。
- 要傳給下一個角色的值（邀請連結、代碼、訂單編號）由主控用 locator 從頁面讀回，不採用 agent 用眼睛抄下的值。（實例：邀請連結裡的大寫 I 被抄成小寫 l。）

## Good Example

```md
你的帶領人帳號已由管理者審核通過。請繼續：登入後開那個讀書會並送審，送審後停下回報。步驟編號接續上一輪，其他規則不變。
```

## Bad Example

- 通知裡寫了入口位置，下一輪「找不找得到入口」就量不到了。

```md
審核通過了。請登入後點左邊的「我的讀書會」→ 右上角「新增」開始填。
```

# Rule 8 - 卡住時先不給提示

- Level: `MUST`
- agent 回報卡住時，先記下卡住的位置、已試過的地方與步數。這是一項發現，不論之後有沒有找到入口。
- 第一次回覆不給位置提示：請它像一般使用者那樣繼續找，再連續 3 次不符才停下，並記下在哪裡找到、從卡住到找到又花了幾步。
- 第二次仍卡住才給提示，只給到能繼續的最小程度（先說「入口在另一個頁面」，仍不行才說頁面名稱）。給過提示的段落在主控筆記記為「用到提示」。

## Good Example

```md
收到卡住的回報，這次不提供位置提示。你列出還有沒試過的地方，請像一般使用者那樣繼續找「開始」的入口；找到就完成第二輪，再連續 3 次不符才停下回報。紀錄裡請記下：你是在哪裡找到的、從卡住到找到又花了幾步。步驟編號接續 011，其他規則不變。
```

## Bad Example

```md
「開始」在儀表板最下面那一區，按下去會跳確認視窗，再按「確認開始」。
```

# Rule 9 - 稽核後處理違規與意外截到的內容

- Level: `MUST`
- Claude Code 的 subagent transcript 在 `~/.claude/projects/<專案代稱>/<session id>/subagents/agent-<agent id>.jsonl`。主控不閱讀 transcript 全文，只看稽核腳本的輸出。
- 稽核列出的違規（用了允許清單外的工具、以元素定位或讀取頁面內容、讀了截圖以外的檔案、前往未允許的網址）：受影響的步驟不當作「只看畫面操作」的證據。違規集中在某一段時，那一段重跑，或在判讀限制註明。
- 剪貼簿按鍵，或其他可能把電腦上與測試無關的內容帶進頁面的動作：
  - 該步與之後到離開那個畫面之前的截圖一律不開啟，主控也不開。
  - 檔名列入隔離清單寫進主控筆記；之後所有 agent 的任務說明與工單都把這些檔案列為禁止開啟、複製、引用。
  - 告知使用者發生了什麼、哪幾張圖、沒有人開啟過，請他決定刪除或保留；當時剪貼簿若是密碼或金鑰，建議另外更換。

# Rule 10 - 環境檢查與留下的測試資料

- Level: `MUST`
- 派出 agent 前照專案規則跑它列的環境檢查（網站回 200、前端已建置、mock 設定開啟、migration 沒有 pending 等），任一條不成立即停。
- 這次建立的帳號與資料列在主控筆記。回報時寫明它們留在哪個資料庫、專案的哪個指令會清掉。
- 不自行執行清除指令：手冊重拍與裁決項目的重現還會用到這些資料，清除由使用者決定。
